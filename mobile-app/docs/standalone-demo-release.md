# Standalone DriveSense demonstration

## Runtime profile

The Release bundle is built with `EXPO_PUBLIC_DRIVESENSE_PROFILE=standalone-demo`. Profiles, drives, alerts and waveform archives stay in the app’s SQLite container. The shared Supabase telemetry client blocks HTTP operations, and profile upload, live upload, catch-up, manual sync and queued deletion exit before cloud work. Existing sync statuses and deletion queues are retained. Opening the database in the demo sets a persistent sync hold. On return to a compatible ordinary build, Settings → Data → Cloud Synchronization requires explicit confirmation to release the hold.

BLE and Live Vitals remain available. Use a synthetic driver and synthetic recordings for displayed demonstration history and any authorized Ask Sensi context. Keep personal-data sharing off during real hardware acquisition. Use the separate signed-in demo account for Ask Sensi v17. General questions omit personal context, and explicit recorded-drive summaries are generated locally. Install into a fresh application container on a test phone where possible. Keep its sign-in and demo data separate from the known-good Debug app.

Hardware Demo and Real Hardware Safety Test are available in the explicit demonstration Release profile. Diagnostic thresholds belong to explicitly started diagnostic instances. Production monitoring still uses the ordinary threshold path. Swift diagnostic probes, the responsiveness screens and voice experiments remain Debug-only. Use an iPhone with iOS 26 and installed on-device voice assets for the bilingual offline test. Downloading the assets during setup may require a connection.

## GitHub Actions and AltStore

The previous workflow used a moving macOS/Xcode toolchain, could run on push, and checked for Bluetooth permission before packaging an unsigned Release app. The revised manual workflow checks that the dispatch ref matches the exact approved SHA and uses macOS 26 ARM, Xcode 26.6 (17F113), iOS SDK 26.5, Node 22.23.5, CocoaPods 1.17.0 and the npm lockfile. It regenerates the Expo SDK 54 native project from the approved commit, resolves Pods, and checks for the local Swift module, SQLite, the embedded JavaScript bundle, device architecture, permission strings and accidental data or credentials. It records the resolved Pod lockfile. A future repeat build can use that verified Pod lockfile to establish dependency reproducibility. [GitHub macOS runner inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md) · [Expo build images](https://docs.expo.dev/build-reference/infrastructure/)

The shared repository is public and its current default branch lacks this workflow. After physical UI and voice approval and Git approval, make the reviewed candidate available in a private build repository. GitHub requires the manual workflow on that repository’s default branch. A private mirror that uses the approved candidate as its default branch satisfies this without merging into shared main. Supply only the public Supabase endpoint and a publishable or legacy anonymous key configured for the existing v17 endpoint. Keep the resulting IPA private to the demo operator because the current production Supabase telemetry policies may allow access using that bundled public project key. The local transport restriction applies inside DriveSense and does not change those server permissions. [GitHub workflow dispatch](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch)

Dispatch the workflow for the exact approved SHA. Download and check `shasum -a 256 -c SHA256SUMS`. Match the SHA in `BUILD.txt`, the IPA filename and the candidate commit. Retain the unsigned IPA hash separately from any re-signed copy. AltStore Classic signs and installs through AltServer, using the operator’s Apple account outside CI. Check the signed app ID, the granted entitlements, microphone and speech permission prompts, and SecureStore persistence after installation and refresh. A changed app ID can mean a fresh SQLite container and a new Ask Sensi sign-in. Free-account signing requires periodic refresh and may have app slots or App ID limits. Use a test device/container and confirm AltStore can refresh the build before the recording. [AltStore app IDs](https://faq.altstore.io/altstore-classic/app-ids) · [AltServer](https://faq.altstore.io/release-notes/altserver)

Fallback is a disposable checkout of the same approved commit. Use the same toolchain, ignored local configuration limited to the public endpoint/key, explicit demo profile and Release bundle checks. Archive and export through Xcode using an authorized signing identity when available. Preserve SHA-256 and build metadata for the exported IPA. Keep the existing native project, Metro process, Debug binary and rescue artifacts separate from both packaging paths.

## Physical acceptance

- Before packaging, repeat final bilingual UI and voice validation on the existing known-good Debug app. Confirm early speech capture, accurate transcript completion, audible acknowledgment and explicit contact authorization with a controlled test contact.
- After the separately approved build, install the Release IPA through AltStore. Disconnect from the development Mac and launch in airplane mode with Bluetooth enabled. Verify genuine BLE acquisition, Live Vitals, local save, history and waveform reopening, baseline, driver switching/deletion, onboarding, and Safety Sensi in English and Spanish. Check the privacy disclosure and sync statuses in both languages and themes.
- Run Hardware Demo and Real Hardware Safety Test by explicit selection. Exit each and confirm ordinary Live Vitals and normal policy resume. Check readiness and contact handoff. Keep real hardware readings local.
- Reconnect to the internet. Sign in, ask one general question with sharing disabled, verify a synthetic local summary consumes no reservation, then use one authorized synthetic-context request. Check history and consent. During the test verify that network traffic contains no shared telemetry REST or storage requests.
